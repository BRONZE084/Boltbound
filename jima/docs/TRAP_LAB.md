# 道具实验室

浏览器入口为 `/lab.html`，也可从游戏首页点击「道具实验室」。界面沿用游戏的纸色、青绿与珊瑚色、工业零件素材和原版地图，以搭建、陷阱与道具交互为实验重点，不计分、不限时。

## 启动

在 `jima/` 目录运行：

```bash
npm ci
npm run dev:lab
```

打开 `http://localhost:5173/lab.html`。实验室独立在浏览器内运行，不需要房间服务器。已有 `npm run dev` 服务时，直接打开相同路径即可，无需再启动一个 Vite。

生产构建 `npm run build:desktop` 同时生成 `dist/index.html` 和 `dist/lab.html`。两页共享游戏场景与公共代码；`npm start` 可提供构建后的两页。

## 推荐的第一次实验

1. 选择「尖刺」，在精确搭建中输入 `X=480, Y=320`，点击「在此处放置」。
2. 点击场地工具栏的「出生点」，将红色准星放到尖刺正上方。
3. 点击「开始试用」，观察下落和接触死亡。
4. 按 `R` 复位角色重复测试；返回搭建后旋转尖刺，比较不同方向的接触。
5. 在试用模式选中「防护盾」再使用，验证它能抵挡负面道具，但不能抵挡尖刺。

## 搭建与试用

| 操作 | 用法 |
| --- | --- |
| 选件与连续放置 | 左侧选择零件，在画布点击或拖动预览后松开；没有轮次配额 |
| 旋转 | 搭建时空格、`R` 或右侧旋转按钮，每次 90 度 |
| 精确放置 | 右侧输入 X/Y，按 20 像素网格填写，再点击放置 |
| 查看已有零件 | 「选择」工具点击零件，显示黄色边框和说明 |
| 删除 | 「删除」工具点击，或选中后按 Delete / 点击删除按钮 |
| 撤销与重做 | 工具栏按钮、Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z |
| 清空 | 清空零件并恢复原始出生点，可以撤销 |
| 设置测试出生点 | 「出生点」工具点击画布；可设置在陷阱附近复现交互 |
| 控制角色 | A/D 或左右箭头移动，W/上箭头/空格跳跃与二段跳，也有屏幕方向按钮 |
| 使用主动道具 | 右侧使用按钮或 Q；搭建模式下该按钮先进入试用 |
| 测试负面道具 | 默认由陪练施放到当前可操控角色，也可改为向陪练施放观察状态 |
| 复位角色 | 试用时 R 或按钮；清除效果与冷却，保留当前试用场地 |
| 重置实验 | 从搭建方案恢复所有零件，复位角色、效果和死亡计数 |
| 碰撞体 / 音效 | 画布下方勾选碰撞体，角色工具栏开关原版音效 |

搭建范围覆盖完整的 `1600×900` 画面，中心坐标为 `X=0–1600`、`Y=0–900`，仍吸附到 20 像素网格。边缘允许零件部分伸出画面；出生区不再预留禁建区域；绿色保护区严格等于旗子碰撞体 `X=1465–1555、Y=530–660`，不额外预留左右或上方空间；实体可与其贴边，侵入和运动遮挡会拒绝。其余位置的运动轨迹和机关作用范围不占用搭建空间。实际零件实体、当前人物和传送出口仍检查占用冲突，边缘传送出口按人物尺寸收回画面内。红色预览和右侧提示说明当前不能放置的原因。测试出生点是实验辅助功能，允许在完成搭建后将人物移到危险位置，因此一进入试用可能立即死亡。

「搭建」类的横梁、方箱、移动路障和冰面可以贴边叠放、左右拼接，也支持旋转后的边缘接合；放置时实体相互穿入仍会拒绝。例如依次放置横梁 `(480, 320)`、方箱 `(480, 260)`、冰面 `(480, 200)`，均保持 0°，即可得到三层叠放结构；将出生点设为 `(480, 100)` 后开始试用，角色可落在顶层冰面上。

移动路障使用独立运动层，显示在固定零件上方、人物下方，运行时可以穿过其他零件，仍与角色碰撞；静态零件不会绑定或随它移动。放置时只要求初始实体不重叠，轨迹可以与已有零件相交，运行时行程按画面边缘缩短，只在旗子碰撞体保护区检查整段轨迹。可先放路障 `(480, 600)`，再放方箱 `(600, 600)`，均为 0°，开始试用后路障将穿过方箱；两者先后顺序均可。

运动交互约定：人物与场景、道具按各自规则发生阻挡、承托或危险触发；道具之间不进行实体碰撞解算，运动互不阻挡。显示层级由独立图层控制，碰撞关系由物理组与人物碰撞注册控制。

横向和纵向移动路障都能承托人物一起移动。人物无操作、无阻挡时保持相对位置与脚底贴合，仍可正常行走、跳离及重新落地。侧墙会限制人物位移，平台继续从脚下滑过；顶板阻挡、走离、跳离、传送复位或平台被移除后解除相应承托。位置按每个显示帧的实际位移传递，关闭重复的摩擦搬运，避免高低帧率造成滑动；行走动画改变碰撞体尺寸时也以脚底保持贴合。

新增「搭建」类零件：风车平台（`windmill`）有四个 `120×24` 的水平落脚平台，绕中心以半径 120、每圈 8 秒转动；轮辐为连接装饰，只有四个平台承托人物。旋转方箱（`rotatingCrate`）为 `80×80`，绕中心每 6 秒转动一圈，每转 90° 停顿 0.35 秒，随后用 1.15 秒平滑转向下一个角度；按实际倾斜箱面碰撞，不使用外接方框阻挡人物。两者的旋转按钮调整初始角度，进入试用后开始转动；返回搭建或重置实验时恢复初始姿态，单独复位角色不重启机关时钟。路障、风车、旋转方箱与旋转电锯均位于静止结构上方、人物下方。

可在 `(400,560)` 放置风车，在 `(500,480)` 放置静态方箱，再在 `(1000,560)` 放置旋转方箱；把出生点设为 `(520,510)` 后开始试用，观察搭乘与前方穿行。

使用道具时保留原始持续时间、冷却、护盾、负面效果互斥与免疫规则；实验室取消每轮只能使用一次的配额，允许反复补充。同一时刻只有一个自身增益和一个负面效果槽，不把多种增益无限叠加。

爆炸复用服务端的实际范围和传送门组移除规则，只破坏试用场地。返回搭建或重置实验会恢复原方案；「复位角色」不会恢复炸毁的零件。到达终点只记录事件，实验继续。

## 源码中的 25 种零件与道具

| 分类 | 内容 |
| --- | --- |
| 可搭建零件（16） | 横梁、方箱、弹簧、尖刺、风机、移动路障、风车平台、旋转方箱、黑洞、传送门、传送带、冰面、电锯、炮台、激光器、弹力保险杠 |
| 自身增益（4） | 涡轮增压、跳跃背包、防护盾、强力抓地 |
| 指定目标干扰（4） | 减速胶、重力锤、反向器、烟雾罐 |
| 即时道具（1） | 爆破炸弹 |

列表、名称和数值动态读取 `shared/gameConfig.js` 的 `PIECES` / `ACTIVE_ITEMS`；图片读取 `shared/gameAssets.js`。没有为实验室复制一套道具数值。

右侧显示当前配置的全部数值参数。尺寸、距离为逻辑像素，`Ms` 参数统一换算成秒；速度、加速度等保持源码数值。少数角色运动系数仍在原版场景内，不作为实验室可编辑参数。

`src/lab/catalog.js` 为现有行为补充中文说明和测试提示，新增机关时应同步维护提示。人物运动、碰撞、弹射、传送、风力、冰面和道具视觉效果由 `BoltboundScene` 执行；`LabScene` 仅补充编辑工具和出生点标记。

`LabSession` 提供本地实验状态和无限选件/补充，使用共享的放置规则、目标可用性判定以及服务端的纯函数 `resolveBombBlast`。游戏本体和微信入口不使用实验室状态。该页面适合验证单机交互；陪练固定站立，不执行寻路，也不替代多人联机协议和同步测试。

## 保存与协作

搭建操作自动保存到当前浏览器的 `boltbound.trap-lab.plan.v1`，不覆盖游戏设置。自动保存按浏览器来源隔离；换浏览器、域名或端口请用 JSON 交换方案。

点击「导出方案」可将零件类型、位置、旋转、出生点保存为 JSON，交给其他开发者复现。导入会校验格式、数量和放置规则，失败时保留当前方案；成功导入也支持撤销。单份方案最多 300 件零件。旧浏览器方案若含遮挡旗子的零件，会完整保留在搭建模式并提示清理，避免自动丢失原有设计；清理前不能开始试用。新的放置与 JSON 导入均拒绝终点遮挡。

编辑时删除一扇已配对传送门会同时删除其配对门，并支持整组撤销，避免剩余传送门重新配对或变成出口被堵住的单门，从而产生无法重新导入的方案。

## 验证

```bash
npm run test:lab
npm run check:all
npm run build:desktop
npm run test:lab:browser
```

浏览器测试使用仓库已有的 Playwright，Linux 优先使用 `/usr/bin/google-chrome`，其他环境可设置 `LAB_BROWSER_PATH` 为已有 Chromium/Chrome 的可执行文件路径，或使用 Playwright 已安装的 Chromium。默认测试生产构建，也可用 `LAB_TEST_DEV=1` 测试 Vite 开发页面。

测试覆盖源码道具目录、画面四角精确放置、底边鼠标预览与点击、刷新恢复、放置拒绝、旋转、贴边堆叠预览与点击放置、堆叠后的碰撞承托、路障独立图层与横纵穿行、删除、撤销重做、JSON 往返、刷新恢复，以及原版场景中的跳跃、反向控制、护盾清除负面、烟雾、炸弹恢复、尖刺致死、复位和窄屏操作。报告与截图保存在忽略提交的 `artifacts/trap-lab-browser/`，其中 `stacking.png` 展示三层搭建结构与角色承托，`barrier-crossing.png` 展示路障穿行。

路障逐帧回归在真实 Phaser 场景中模拟 30、60、120 FPS 及不均匀帧间隔，分别检查 0°、90°、180°、270° 的图片与碰撞体对齐、既定轨迹、无滑动承托及主动跳离，并补充自然落地、走下平台、侧墙和顶板阻挡、传送、平台移除、重置试用验证。测量结果写入 `artifacts/trap-lab-browser/barrier-motion.json` 和 `barrier-interactions.json`。

新增旋转件回归报告为 `artifacts/trap-lab-browser/rotating-motion.json`，覆盖风车四平台、不同帧率的整圈搭乘及跳离、旋转方箱落地、真实箱面与空角碰撞、跳离与重置。`rotating-platforms.png` 和 `goal-protection.png` 展示新零件和旗子碰撞体保护区。
